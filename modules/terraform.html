🌍 01 · le problème infra
// avant terraform
Créer une VM, un réseau, un load balancer sur AWS : 30 clics dans la console. Reproduire en staging ? Re-cliquer. Auditer les changements ? Impossible. Rollback une modif cassée ? Bonne chance. Terraform définit l'infrastructure en code — versionné, auditable, reproductible.
💡 Analogie
Terraform est comme un plan d'architecte. Au lieu de construire une maison en improvisant, tu écris le plan une fois (fichiers .tf), et Terraform construit exactement la même maison 10 fois si besoin — dev, staging, prod.
🧠 02 · concepts clés
// concepts terraform
ConceptDescription
ProviderPlugin pour interagir avec un cloud (AWS, Azure, GCP) ou service (GitHub, Datadog).
ResourceComposant d'infra : VM, bucket S3, réseau. Défini en code et géré par Terraform.
StateFichier terraform.tfstate qui trace l'état actuel de l'infra. Ne jamais l'éditer manuellement.
PlanTerraform calcule les changements à appliquer (créer, modifier, détruire) avant exécution.
ModuleEnsemble de ressources réutilisables. Comme une fonction en programmation.
BackendOù stocker le state (local, S3, Terraform Cloud). S3 + DynamoDB pour le lock en équipe.
// workflow terraform
  • ▸terraform init : télécharge les providers et initialise le backend.
  • ▸terraform plan : affiche un preview des changements sans rien appliquer.
  • ▸terraform apply : applique les changements et met à jour le state.
  • ▸terraform destroy : détruit toute l'infra définie.
⌨️ 03 · commandes de référence
// main.tf — aws ec2 + s3
terraform infrastructure aws 
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "prod/terraform.tfstate"
    region = "eu-west-1"
  }
}

provider "aws" {
  region = "eu-west-1"
}

resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"

  tags = {
    Name        = "ViaOps-Web"
    Environment = "production"
  }
}

resource "aws_s3_bucket" "assets" {
  bucket = "viaops-assets-bucket"
}

# Versioning = ressource séparée (provider AWS v4+)
resource "aws_s3_bucket_versioning" "assets" {
  bucket = aws_s3_bucket.assets.id
  versioning_configuration {
    status = "Enabled"
  }
}

output "instance_ip" {
  value = aws_instance.web.public_ip
}
// commandes terraform essentielles
bash terraform cli 
# Initialiser le projet
terraform init

# Prévisualiser les changements
terraform plan

# Appliquer les changements
terraform apply

# Appliquer sans confirmation
terraform apply -auto-approve

# Détruire toute l'infrastructure
terraform destroy

# Formater les fichiers .tf
terraform fmt

# Valider la syntaxe
terraform validate

💼 05 · ce qu'il faut dire en entretien recruteur
// questions fréquentes · réponses attendues
▸ "C'est quoi le state Terraform et pourquoi est-il critique ?"
"Le state (terraform.tfstate) trace l'état actuel de l'infra. Si tu le perds, Terraform ne sait plus ce qu'il gère et peut recréer ou détruire des ressources par erreur. En équipe, on le stocke dans S3 avec un lock DynamoDB."
▸ "Pourquoi faire un terraform plan avant apply ?"
"plan affiche un preview des changements — ce qui va être créé, modifié ou détruit. Ça évite les surprises et permet de valider avant d'appliquer réellement."
▸ "Comment gérer plusieurs environnements avec Terraform ?"
"Avec des workspaces (terraform workspace) ou des dossiers séparés (dev/, prod/) avec des fichiers tfvars différents. Chacun a son propre state."
