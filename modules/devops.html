01 · le problème culture
// contexte
Avant le DevOps, le développement et les opérations étaient deux silos séparés. Les devs livraient du code, les ops le déployaient — souvent des semaines plus tard, souvent avec des conflits. Résultat : des déploiements rares, risqués et douloureux.
Analogie
Imagine une chaîne de restauration où les cuisiniers ne parlent jamais aux serveurs. Les plats arrivent froids, mal présentés, personne ne sait qui est responsable. Le DevOps, c'est mettre tout le monde autour de la même table.
02 · concepts clés
// CALMS — le framework DevOps
ConceptDescription
C — CultureCollaboration entre Dev et Ops. Responsabilité partagée. Pas de silos.
A — AutomatisationTout ce qui est répétitif doit être automatisé : tests, déploiements, infrastructure.
L — LeanÉliminer les gaspillages. Livrer de la valeur en petits incréments continus.
M — MesureTout mesurer : temps de déploiement, taux d'erreurs, disponibilité (SLI/SLO).
S — SharingPartager les outils, les pratiques, les post-mortems. Apprendre des échecs.
// concepts fondamentaux
  • ▸CI — Intégration Continue : chaque commit déclenche automatiquement build + tests.
  • ▸CD — Déploiement Continu : le code validé part en production automatiquement.
  • ▸IaC — Infrastructure as Code : l'infra est définie en fichiers versionnés, pas cliquée à la main.
  • ▸Shift Left : tester et sécuriser tôt dans le cycle, pas à la fin.
  • ▸Feedback loop : réduire le temps entre un commit et le retour utilisateur.
03 · place dans le pipeline
Le DevOps n'est pas un outil — c'est la philosophie qui donne du sens à tous les autres outils du pipeline. Sans culture DevOps, Docker reste un outil de packaging, Kubernetes reste complexe, le monitoring reste réactif.

# Le cycle DevOps infini

  Plan → Code → Build → Test → Release → Deploy → Operate → Monitor
    ↑                                                              ↓
    └──────────────── Feedback continu ◄───────────────────────────┘

# Chaque outil ViaOps couvre une étape :
  DevOps      → Culture (toutes les étapes)
  Docker      → Build / Package
  Jenkins     → CI/CD (Build → Test → Deploy)
  SonarQube   → Test (qualité du code)
  Kubernetes  → Deploy / Operate
  Terraform   → Infra as Code (Plan)
  Prometheus  → Monitor / Feedback
  Trivy       → Security (Shift Left)
  IA DevOps   → Accélérateur transversal

05 · ce qu'il faut dire en entretien recruteur
// questions fréquentes · réponses attendues
▸ "C'est quoi le DevOps pour toi ?"
"C'est une culture de collaboration entre Dev et Ops, basée sur l'automatisation et la livraison continue, pour réduire le temps entre un commit et la valeur livrée à l'utilisateur."
▸ "Quelle différence entre CI et CD ?"
"CI = intégrer et tester automatiquement à chaque commit. CD = déployer automatiquement le code validé en production ou en staging."
▸ "Qu'est-ce que le Shift Left ?"
"C'est tester et sécuriser tôt dans le cycle — pas attendre la fin pour trouver les bugs ou les vulnérabilités."
