01 · le problème gitops
// avant argocd
Jenkins build et teste ton code, Kubernetes peut l'exécuter, mais qui déploie vers K8s ? Qui garantit que ton cluster reflète exactement le code Git ? Qui détecte les drifts de config ? ArgoCD automatise le déploiement GitOps : ton repo Git est la source de vérité, ArgoCD synchronise K8s automatiquement.
Analogie
Git = le plan d'architecte. Kubernetes = le chantier. ArgoCD = le contremaître qui vérifie que le chantier correspond au plan, répare les écarts automatiquement, et prévient si quelqu'un modifie sans permission.
02 · concepts clés
// concepts argocd
ConceptDescription
GitOpsPhilosophie : Git est la source unique de vérité. Tout changement passe par Git (pull request).
ApplicationObjet ArgoCD qui lie un repo Git à un namespace K8s. Définit quoi déployer et où.
SyncArgoCD compare Git vs K8s. Si différence détectée, il synchronise (manuel ou auto).
Drift DetectionDétection automatique si quelqu'un modifie K8s directement (kubectl apply). ArgoCD alerte ou rollback.
// workflow gitops avec argocd
  • ▸Développeur : Push code → Jenkins CI build/test → Push image Docker.
  • ▸DevOps : Update deployment.yaml avec nouvelle image → Commit Git.
  • ▸ArgoCD : Détecte changement Git → Sync automatique vers K8s → Deploy.
  • ▸Monitoring : Prometheus surveille la nouvelle version. Si erreur → Rollback Git.
03 · commandes de référence
// application.yaml — argocd app
yaml argocd application 
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: mon-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/user/mon-app
    targetRevision: HEAD  # Branche main
    path: k8s  # Dossier contenant les manifests K8s
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  syncPolicy:
    automated:
      prune: true  # Supprimer ressources absentes de Git
      selfHeal: true  # Rollback si drift détecté
    syncOptions:
    - CreateNamespace=true
// commandes argocd cli
bash argocd cli 
# Créer une application
argocd app create mon-app \
  --repo https://github.com/user/mon-app \
  --path k8s \
  --dest-server https://kubernetes.default.svc \
  --dest-namespace production

# Lister les applications
argocd app list

# Voir le statut de sync
argocd app get mon-app

# Synchroniser manuellement
argocd app sync mon-app

# Rollback à une version précédente
argocd app rollback mon-app 2

# Voir les différences Git vs K8s
argocd app diff mon-app

05 · ce qu'il faut dire en entretien recruteur
// questions fréquentes · réponses attendues
▸ "C'est quoi GitOps ?"
"GitOps est une philosophie où Git devient la source unique de vérité pour l'infrastructure et les déploiements. Tout changement passe par Git (pull request), et un outil comme ArgoCD synchronise automatiquement l'état désiré vers Kubernetes."
▸ "Différence entre CI et CD dans votre pipeline ?"
"CI (Jenkins) build et teste le code à chaque commit. CD (ArgoCD) déploie automatiquement vers Kubernetes quand le manifest Git change. Jenkins produit l'artefact, ArgoCD le déploie via GitOps."
▸ "Pourquoi ArgoCD plutôt que kubectl apply dans Jenkins ?"
"ArgoCD offre drift detection, rollback automatique, audit trail Git, et un état toujours synchronisé. kubectl apply dans Jenkins est unidirectionnel et ne détecte pas les modifications manuelles post-déploiement."
