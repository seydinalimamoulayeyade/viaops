01 · le problème deploy
// avant kubernetes
Docker résout "ça marche sur ma machine", mais qui gère 100 conteneurs en production ? Qui les redémarre si un crash ? Qui distribue la charge ? Qui scale automatiquement ? Kubernetes orchestre des milliers de conteneurs : déploiement, scaling, self-healing, load balancing.
Analogie
Docker = une voiture. Kubernetes = la ville entière avec ses routes, feux de circulation, ambulances. Il gère le trafic (load balancing), répare les pannes (self-healing), ajoute des routes si besoin (scaling).
02 · concepts clés
// concepts kubernetes
ConceptDescription
PodUnité de base K8s. Encapsule 1+ conteneurs qui partagent réseau et stockage.
DeploymentDéfinit l'état désiré : 3 replicas de mon app. K8s garantit cet état en permanence.
ServicePoint d'accès stable (IP fixe) pour un ensemble de pods. Load balancing intégré.
NamespaceIsolation logique. Séparer dev, staging, prod dans le même cluster.
// architecture k8s
  • ▸Control Plane : cerveau du cluster (API server, scheduler, controller).
  • ▸Worker Nodes : machines qui exécutent les pods.
  • ▸etcd : base de données clé-valeur qui stocke l'état du cluster.
  • ▸kubelet : agent sur chaque node qui communique avec l'API server.
03 · commandes de référence
// deployment.yaml — node.js app
yaml deployment + service 
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mon-app
spec:
  replicas: 3  # 3 pods identiques
  selector:
    matchLabels:
      app: mon-app
  template:
    metadata:
      labels:
        app: mon-app
    spec:
      containers:
      - name: api
        image: username/mon-app:1.0
        ports:
        - containerPort: 3000
        env:
        - name: NODE_ENV
          value: "production"
---
apiVersion: v1
kind: Service
metadata:
  name: mon-app-svc
spec:
  selector:
    app: mon-app
  ports:
  - port: 80
    targetPort: 3000
  type: LoadBalancer
// commandes kubectl essentielles
bash kubectl cli 
# Appliquer un fichier YAML
kubectl apply -f deployment.yaml

# Lister les pods
kubectl get pods

# Voir les logs d'un pod
kubectl logs mon-app-xyz123 -f

# Entrer dans un pod
kubectl exec -it mon-app-xyz123 -- sh

# Scaler un deployment
kubectl scale deployment mon-app --replicas=5

# Rollback d'un deployment
kubectl rollout undo deployment/mon-app

05 · ce qu'il faut dire en entretien recruteur
// questions fréquentes · réponses attendues
▸ "Quelle différence entre un Pod et un Deployment ?"
"Un Pod est l'unité d'exécution — un ou plusieurs conteneurs. Un Deployment gère plusieurs Pods identiques (replicas) et garantit leur état désiré avec self-healing et rolling updates."
▸ "C'est quoi un Service dans Kubernetes ?"
"C'est un point d'accès stable (IP fixe) pour un ensemble de Pods. Les Pods peuvent mourir et être recréés avec de nouvelles IPs, le Service lui reste constant et load balance entre eux."
▸ "Comment Kubernetes fait du self-healing ?"
"Le controller manager surveille en permanence l'état actuel vs l'état désiré. Si un Pod crash, il en recrée un automatiquement pour maintenir le nombre de replicas défini."
