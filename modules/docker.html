🐳 01 · le problème build
// avant docker
"Ça marche sur ma machine" — la phrase la plus redoutée en équipe. Chaque environnement avait ses propres dépendances, versions, configs. Déployer une app = des heures de configuration manuelle, des bugs impossibles à reproduire. Docker résout ça en empaquetant l'app et tout son environnement dans un conteneur portable.
💡 Analogie
Un conteneur Docker = un conteneur maritime. Peu importe ce qu'il contient, il s'adapte à n'importe quel navire, port, grue. Ton app tourne de la même façon sur ton laptop, en CI/CD, ou en production AWS.
🧠 02 · concepts clés
// image vs conteneur
ConceptDescription
ImageTemplate figé, read-only. Le blueprint de ton app. Construite avec un Dockerfile.
ConteneurInstance vivante d'une image. Possède son propre layer d'écriture éphémère.
DockerfileFichier texte avec les instructions pour construire une image, couche par couche.
RegistryDépôt d'images. Docker Hub est le public, tu peux avoir le tien en privé.
VolumeStockage persistant monté dans le conteneur. Les données survivent au redémarrage.
NetworkLes conteneurs d'un même Compose se parlent via leur nom de service.
// analogie POO
💡 Image vs Conteneur
Image = la classe en POO. Conteneur = l'instance. Tu peux créer 10 conteneurs à partir d'une même image — chacun isolé, chacun avec son propre état.
⌨️ 03 · commandes de référence
// dockerfile — node.js app
Dockerfile multi-stage · production ready 
# Stage 1 — builder
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2 — production (image légère)
FROM node:20-alpine AS production
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY package*.json ./
RUN npm ci --omit=dev
EXPOSE 3000
CMD ["node", "dist/server.js"]
// commandes essentielles
bash cli de référence 
# Build une image
docker build -t mon-app:1.0 .

# Lancer un conteneur (detached + port mappé)
docker run -d -p 3000:3000 --name api mon-app:1.0

# Logs en temps réel
docker logs -f api

# Entrer dans un conteneur
docker exec -it api sh

# Stopper + supprimer
docker stop api && docker rm api

# Push sur Docker Hub
docker tag mon-app:1.0 username/mon-app:1.0
docker push username/mon-app:1.0
// docker compose — stack MERN
yaml docker-compose.yml 
services:
  api:
    build: .
    ports: ["3000:3000"]
    environment:
      - MONGO_URI=mongodb://db:27017/myapp
    depends_on: [db]

  db:

💼 05 · ce qu'il faut dire en entretien recruteur
// questions fréquentes · réponses attendues
▸ "Quelle différence entre image et conteneur ?"
"L'image est un template immutable — le blueprint. Le conteneur est une instance en cours d'exécution de cette image, avec son propre layer d'écriture."
▸ "C'est quoi un multi-stage build ?"
"C'est construire l'image en plusieurs étapes : une pour compiler, une pour la production. Résultat : une image légère qui ne contient que le strict nécessaire."
▸ "Pourquoi utiliser Docker Compose ?"
"Pour orchestrer plusieurs services localement en un seul fichier YAML — api, base de données, cache — et les démarrer d'une commande : docker compose up."
