01 · le problème security
// avant trivy
Ton image Docker contient une version de nginx avec une CVE critique. Tu l'as déployée en prod. Un attaquant exploite la faille. Ton équipe découvre ça 3 semaines après. Trivy scanne images Docker, code, dépendances et détecte les vulnérabilités AVANT le déploiement.
Analogie
Trivy est comme un détecteur de métaux à l'aéroport. Il scanne ton bagage (image Docker) avant l'embarquement (déploiement) et détecte tout ce qui est dangereux (CVEs, malwares, secrets exposés).
02 · concepts clés
// concepts trivy
ConceptDescription
CVECommon Vulnerabilities and Exposures. Identifiant unique d'une faille de sécurité (CVE-2024-1234).
SeverityGravité de la vulnérabilité : LOW, MEDIUM, HIGH, CRITICAL.
SBOMSoftware Bill of Materials. Liste exhaustive de toutes les dépendances et leurs versions.
ScannerTrivy supporte Docker images, filesystem, Git repos, Kubernetes manifests, IaC (Terraform).
DatabaseTrivy télécharge une base de vulnérabilités (NVD, Alpine SecDB, etc.) mise à jour quotidiennement.
Policy as CodeDéfinir des règles de sécurité en OPA/Rego. Bloquer le déploiement si CRITICAL présent.
// shift left security
  • ▸Dev local : scanner avant commit avec pre-commit hook.
  • ▸CI/CD : intégrer Trivy dans le pipeline — build échoue si HIGH/CRITICAL.
  • ▸Registry : scanner les images dans le registry régulièrement (nouvelles CVEs).
  • ▸Runtime : scanner les conteneurs en prod avec Trivy Operator (Kubernetes).
03 · commandes de référence
// commandes trivy essentielles
bash trivy cli 
# Scanner une image Docker locale
trivy image mon-app:latest

# Scanner uniquement les vulnérabilités HIGH et CRITICAL
trivy image --severity HIGH,CRITICAL mon-app:latest

# Scanner et exporter en JSON
trivy image -f json -o results.json mon-app:latest

# Scanner un dossier (code source + dépendances)
trivy fs --scanners vuln,secret .

# Scanner un repo Git distant
trivy repo https://github.com/user/repo

# Scanner des manifests Kubernetes
trivy config ./k8s/

# Générer un SBOM
trivy image --format cyclonedx -o sbom.json mon-app:latest
// intégration github actions
yaml .github/workflows/security.yml 
name: Security Scan

on: [push, pull_request]

jobs:
  trivy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build Docker image
        run: docker build -t mon-app:${{ github.sha }} .

      - name: Run Trivy scanner
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: 'mon-app:${{ github.sha }}'
          format: 'sarif'
          output: 'trivy-results.sarif'
          severity: 'HIGH,CRITICAL'
          exit-code: '1'  # Fail si vulnérabilités

      - name: Upload results to GitHub Security
        uses: github/codeql-action/upload-sarif@v2
        with:
          sarif_file: 'trivy-results.sarif'

05 · ce qu'il faut dire en entretien recruteur
// questions fréquentes · réponses attendues
▸ "Pourquoi utiliser Trivy plutôt que Snyk ou Clair ?"
"Trivy est open source, gratuit, rapide et supporte plus de formats : images Docker, filesystem, Git repos, IaC, Kubernetes. Il est aussi plus facile à intégrer dans le CI/CD."
▸ "Comment Trivy détecte-t-il les vulnérabilités ?"
"Il extrait les dépendances et leurs versions de l'image (OS packages, libraries), puis les compare à une base de CVEs mise à jour quotidiennement depuis NVD, Alpine SecDB, etc."
▸ "C'est quoi le Shift Left Security ?"
"C'est détecter les failles de sécurité tôt dans le cycle — dès le dev, pas en prod. Trivy dans le CI/CD bloque le déploiement avant que la vulnérabilité n'atteigne la production."
